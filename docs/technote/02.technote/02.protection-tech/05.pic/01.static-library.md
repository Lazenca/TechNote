# **Static Library**

## **Explanation**

* **A static library is an archive file (.a) containing one or more object files.**
  + When building an executable that uses a static library, the linker copies the required code from the static library directly into the executable binary.
  + When multiple programs are built using the same static library, identical copies of the library function code are bundled into each binary.

## **Example**

### **Source code (Library)**

```c
#include <stdio.h>
 
void lazenca(int a){
    printf("lazenca.0x%d\n",a);
}
```

### **Source code (Executable)**

```c
#include <stdio.h>

void main(){
    lazenca(10,10);
}
```

## **Build**

* Generate object code using GCC's `-c` option.
* Create the archive library file (`.a`) using the `ar` utility.

```bash title="Build"
lazenca0x0@ubuntu:~/Documents/Definition/protection/PIC$ gcc -c lazenca.c
lazenca0x0@ubuntu:~/Documents/Definition/protection/PIC$ ar vr libstatic.a lazenca.o 
ar: creating libstatic.a
a - lazenca.o
lazenca0x0@ubuntu:~/Documents/Definition/protection/PIC$ gcc -o testStatic test.c libstatic.a 
test.c: In function 'main':
test.c:4:5: warning: implicit declaration of function 'lazenca' [-Wimplicit-function-declaration]
     lazenca(10,10);
     ^
lazenca0x0@ubuntu:~/Documents/Definition/protection/PIC$
```

## **Run**

```bash title="Run"
lazenca0x0@ubuntu:~/Documents/Definition/protection/PIC$ ./testStatic 
Lazenca.0x10
lazenca0x0@ubuntu:~/Documents/Definition/protection/PIC$
```

## **Check for shared library in the executable file**

* Because this binary uses a static library instead of a shared library, the custom library is embedded directly into the binary and does not appear in `ldd` output.

```bash title="Check"
lazenca0x0@ubuntu:~/Documents/Definition/protection/PIC$ ldd ./testStatic 
	linux-vdso.so.1 =>  (0x00007ffdad1f7000)
	libc.so.6 => /lib/x86_64-linux-gnu/libc.so.6 (0x00007fc279822000)
	/lib64/ld-linux-x86-64.so.2 (0x00005626edadf000)
lazenca0x0@ubuntu:~/Documents/Definition/protection/PIC$
```
