# **Shared Library**

## **Explanation**

* **A shared library combines multiple object files into a single shared object (.so) that can be shared across multiple programs.**
  + Instead of embedding library function code directly into the executable binary, the binary dynamically references the shared library at runtime.
  + When an executable linked against a shared library is launched, the dynamic linker/loader (`ld.so`) locates the required shared library and maps it into the process memory space.
  + The actual library code does not reside within the executable binary itself; it exists only in the shared library file.
  + Therefore, when distributing the executable, the required shared library must also be present on the target system.
  + Otherwise, a runtime error indicating that the shared library cannot be found will occur.

## **Example**

### **Source code (Shared library)**

```c
#include <stdio.h>
 
void lazenca(int a){
    printf("lazenca.0x%d\n",a);
}
```

### **Source code (Executable)**

```c
#include <stdio.h>

void main(){
    lazenca(10,10);
}
```

## **Build & Setting**

### Build shared library

```bash title="Build"
lazenca0x0@ubuntu:~/Documents/Definition/protection/PIC$ gcc -fPIC -shared -o libPIC.so lazenca.c
```

### **Setting shared library**

* Configure `/etc/ld.so.conf` as shown below:

```
include /etc/ld.so.conf.d/*.conf
```

* Create a configuration file named `libmy.conf` in `/etc/ld.so.conf.d` and add the full directory path to the shared library (`.so`):

```
/home/autolycos/Documents/
```

* Run `ldconfig` to update the library cache so that executables can find the shared library:

```bash
$ sudo ldconfig
```

### Build executable file

```bash title="Build"
lazenca0x0@ubuntu:~/Documents/Definition/protection/PIC$ gcc -o NonPIC test.c -lNonPIC -L.
test.c: In function 'main':

     lazenca(10,10);
     ^
lazenca0x0@ubuntu:~/Documents/Definition/protection/PIC$
```

## **Run**

```bash title="Run"
lazenca0x0@ubuntu:~/Documents/Definition/protection/PIC$ ./NonPIC
```

## **Check for shared library in the executable file**

* `ldd` (List Dynamic Dependencies) is a utility that prints the shared libraries required by an executable.
* Using `ldd`, you can verify that the program dynamically references the shared library.

```bash title="Check"
lazenca0x0@ubuntu:~/Documents/Definition/protection/PIC$ ldd ./NonPIC 
	linux-vdso.so.1 =>  (0x00007fffb8fd9000)
	libNonPIC.so => /home/lazenca0x0/Documents/Definition/protection/PIC/libNonPIC.so (0x00007f866f6d3000)
	libc.so.6 => /lib/x86_64-linux-gnu/libc.so.6 (0x00007f866f309000)
	/lib64/ld-linux-x86-64.so.2 (0x0000564199d90000)
lazenca0x0@ubuntu:~/Documents/Definition/protection/PIC$
```
