# **Concrete execution**

* **Concrete execution is a method of analyzing a program based on actual, concrete values during execution.**

## **Example**

* **Consider the following code demonstrating concrete execution:**
  + This code is very straightforward.
  + Because the condition is a fixed constant `1`, the program always prints "Nice!".
  + No matter how many times the program runs, the execution path and output remain identical.

```c title="ConcreteExecution.c - Example"
#include <stdio.h>

void main(){
	if(1){
		printf("Nice!\n");
	}else{
		printf("Wrong!\n");
	}
}
```

# **Symbolic execution**

* **Symbolic execution analyzes a program by treating unknown inputs as symbolic values (variables) rather than concrete values.**

## **Example**

* **Consider the following code demonstrating symbolic execution:**
  + This program has 3 distinct execution paths depending on the values supplied by the user.
  + `x` and `y` are unknown variables, represented as symbolic values:
    - y = λ
    - x = χ
  + We can derive the following execution paths and constraints:
    - When `z` is not equal to 1000: ((χ * 2) ≠ 1000)
    - When `z` is equal to 1000 and `y` is less than or equal to `z`: (((χ * 2) = 1000) && λ ≤ (χ * 2))
    - When `z` is equal to 1000 and `y` is greater than `z`: (((χ * 2) = 1000) && λ > (χ * 2))

```c title="SymbolicExecution.c - Example"
#include <stdio.h>

void main(){
	int x,y,z;

	scanf("%d",&x);
	scanf("%d",&y);

	z = x * 2;

	if(z == 1000){
		if(y > z){
			printf("Nice!\n");
		}else{
			printf("Wrong!\n");
		}
	}
}
```

## **Limitations**

### Path Explosion

* Exploring all possible executable paths of a large program using symbolic execution is often infeasible.
* The number of executable paths grows exponentially with the size of the program, and unbounded loops can result in infinite execution paths.
* Common strategies to mitigate path explosion include:
  + Using heuristics for general path exploration to maximize code coverage.
  + Parallelizing independent path exploration to reduce execution time.
  + Merging equivalent or similar execution paths.

### Program-Dependent Efficacy

* Symbolic execution is advantageous for path-based program reasoning over input-based analysis used in other testing paradigms.
* However, if very few inputs traverse the same execution path, testing individual inputs directly may be more cost-effective.

### Environment Interactions

* Programs interact with the operating system environment through system calls, signals, and IPC.
* Consistency issues and analysis barriers can arise when symbolic execution encounters external components it cannot model or control.
