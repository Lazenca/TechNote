# **Concolic testing**

* **Concolic testing is an execution technique combining the strengths of Concrete Execution and Symbolic Execution (Conc**~~rete~~ + ~~Symb~~**olic** = **Concolic**).
  + Symbolic execution requires concrete input values to drive execution along specific program paths and maximize code coverage.
    - To generate concrete input values, symbolic execution employs automated theorem provers or constraint solvers based on constraint logic programming.
  + Its primary focus is finding bugs in software rather than formal verification of program correctness.
  + Popular SMT (Satisfiability Modulo Theories) solvers suitable for concolic testing include Z3, STP, Z3str2, Boolector, and others.

## **Example**

* **Consider the following code demonstrating concolic execution:**
* Depending on user input, this program has 3 distinct execution paths.
* `x` and `y` are unknown variables, represented as symbolic variables:
  + y = λ
  + x = χ
* Using an SMT solver, we can solve for concrete input values that satisfy each path condition:
* **Find path and concrete value**

| Path | Condition | Solved |
| --- | --- | --- |
| * When `z` is not equal to 1000 | ((χ \* 2) ≠ 1000) | χ: Any value other than 500 |
| * When `z` is equal to 1000 and `y` is less than or equal to `z` | ((χ \* 2) = 1000, λ ≤ (χ \* 2)) | χ: 500, λ: Value ≤ 1000 |
| * When `z` is equal to 1000 and `y` is greater than `z` | ((χ \* 2) = 1000, λ > (χ \* 2)) | χ: 500, λ: Value > 1000 |

```c title="ConcolicExecution.c - Example"
#include <stdio.h>
 
void main(){
    int x,y,z;
 
    scanf("%d",&x);
    scanf("%d",&y);
 
    z = x * 2;
 
    if(z == 1000){
        if(y > z){
            printf("Nice!\n");
        }else{
            printf("Wrong!\n");
        }
    }
}
```

## **Algorithm**

* **The concolic testing algorithm operates as follows:**
  1. Variables storing user input are treated as symbolic variables during execution.
     1. All other variables are treated as concrete values.
  2. First, the program is executed with random or initial concrete inputs.
  3. During execution, symbolic expressions and branch constraints are extracted along the traversed path.
  4. Symbolic path conditions (constraints) are generated based on the extracted expressions.
  5. The solver negates a branch constraint to generate new concrete inputs, and the program is re-executed with these inputs to explore new branches.
     1. If no satisfying input exists (UNSAT), the engine backtracks to try another path.

## **Limitations**

* **Non-deterministic programs where identical inputs produce differing outputs may cause the program to diverge from the intended symbolic path.**
  + This can cause search non-termination or poor exploration coverage.
* **Even for deterministic programs, various factors can limit exploration in large or infinite path trees:**
  + Inadequate path search heuristics
  + Imprecise symbolic representations / modeling
  + Incomplete theorem proving / solver timeouts
* **Code that heavily scrambles variable state (such as cryptographic primitives and hash functions) generates extremely complex symbolic formulas that are practically intractable for solvers.**
