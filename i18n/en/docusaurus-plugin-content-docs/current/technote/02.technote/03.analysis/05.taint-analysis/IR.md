# **IR (Intermediate Representation)**

* An Intermediate Representation (IR) is the data structure or code used internally by a compiler or virtual machine to represent source code.
* An IR is designed to facilitate further processing, such as optimization and code generation/translation.
* A well-designed IR is capable of representing the source program without loss of information and can represent code independently of the specific source or target language.
* IRs come in several distinct forms:
  + In-memory data structures (e.g., ASTs, DAGs, control-flow graphs)
  + Special tuple-based or stack-based code readable by programs (Intermediate Languages)

## **Intermediate Language**

* **An intermediate language is an abstract machine language designed to aid the analysis of computer programs.**
* It converts source code into a representation suitable for performing optimizations before generating target machine code or object files.
* The design of an intermediate language typically differs from real-world machine languages in three fundamental ways:
  + Each instruction represents a single atomic operation.
  + Control-flow details may be separated from the basic instruction set.
  + The number of available processor registers can be effectively infinite.
* A common format for intermediate languages is Three-Address Code (TAC or 3AC).

:::note[Abstract Machine]
* A theoretical model of a computer hardware or software system, encapsulating computing concepts independently of physical implementation.
:::

## **Three-Address Code (3AC)**

* Three-Address Code is commonly abbreviated as TAC or 3AC.
* TAC is an intermediate code representation used in optimizing compilers to improve code transformation.
* Each TAC instruction has at most three operands and typically combines an assignment operator with a binary operator.
* Because TAC is used as a compiler intermediate language, operands represent symbolic variables rather than concrete memory addresses or physical hardware registers; these are later mapped to real registers during register allocation.

### Example

* The operation `x = (a + b * c) / 2` translates into TAC as follows:

```c title="x = (a + b * c) / 2"
t1 := b * c
t2 := a + t1
t3 := t2 / 2
x := t3
```

* A loop structure is represented in TAC as follows:

```c title="Sample code"
for(i = 0; i < 100; i++){
	val[i] = i;
}
```

```c title="Three-address code"
     t1 := 0
L1:  if t1 >= 100 goto L2
     t2 := t1 * 4
     t3 := val + t2
     *t3 := t1
     t1 := t1 + 1
     goto L1
L2:
```

## **Intermediate Representation Implementations**

### QEMU's TCG (Tiny Code Generator)

* TCG is a code generator in QEMU that transforms target machine instructions into an Intermediate Representation.
* By executing the bytecode generated by TCG via runtime translation (or TCI), QEMU can support emulation across almost any target architecture.
* Supported architectures in QEMU include:
  + ARM, i386, IA-64, PPC, PPC64, s390, SPARC, x86_64

:::note[TCG Readme]
* <https://git.qemu.org/?p=qemu.git;a=blob_plain;f=tcg/README;hb=HEAD>
* <http://repo.or.cz/w/qemu/ar7.git/blob_plain/HEAD:/tcg/tci/README>
:::

### Valgrind's VEX

* Similar to TCG, VEX supports a wide range of architectures and represents various machine instruction sets in an architecture-neutral IR.
* Core object classes in VEX IR include:
  + Expressions
  + Operations
  + Temporary variables
  + Statements
  + Blocks

#### **Example**

* VEX abstracts machine code to make program analysis tractable:

```c title="The following ARM instruction"
subs R2, R2, #8
```

```c title="Becomes this VEX IR"
t0 = GET:I32(16)
t1 = 0x8:I32
t3 = Sub32(t0,t1)
PUT(16) = t3
PUT(68) = 0x59FC8:I32
```

:::note
* <https://docs.angr.io/docs/ir.html>
:::

### LLVM (Low Level Virtual Machine) IR

* LLVM IR maintains a universal, low-level representation while preserving type safety and extensibility.
* LLVM IR uses an unbounded set of typed registers prefixed with the `%` character.
* LLVM supports operations including:
  + Generating LLVM IR from C/C++ source code
  + Compiling IR into native machine code
  + Automated optimization passes

#### **Example**

* Generating LLVM IR from C code:

```bash title="Install LLVM and Clang"
$ sudo aptitude install llvm clang
```

```c title="Sample code"
int sample(int a,int b) {
    	return a*b;
}
```

```c title="LLVM IR"
lazenca0x0@ubuntu:~$ cat sample.ll 
; ModuleID = 'test.c'
target datalayout = "e-m:e-i64:64-f80:128-n8:16:32:64-S128"
target triple = "x86_64-pc-linux-gnu"

; Function Attrs: norecurse nounwind optsize readnone uwtable
define i32 @sample(i32 %a, i32 %b) #0 {
  %1 = mul nsw i32 %b, %a
  ret i32 %1
}

attributes #0 = { norecurse nounwind optsize readnone uwtable "disable-tail-calls"="false" "less-precise-fpmad"="false" "no-frame-pointer-elim"="false" "no-infs-fp-math"="false" "no-nans-fp-math"="false" "stack-protector-buffer-size"="8" "target-cpu"="x86-64" "target-features"="+fxsr,+mmx,+sse,+sse2" "unsafe-fp-math"="false" "use-soft-float"="false" }

!llvm.ident = !{!0}

!0 = !{!"clang version 3.8.0-2ubuntu4 (tags/RELEASE_380/final)"}
lazenca0x0@ubuntu:~$
```
